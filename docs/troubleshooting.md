## E2E cannot find the built extension or Chromium

**Symptom:** `apps/extension/e2e` specs fail to launch, the extension never
loads, or Playwright reports a missing browser executable.

**Cause:** The specs load the real build output at
`apps/extension/.output/chrome-mv3` (see `apps/extension/e2e/fixtures.ts` and
[ADR 0003](adr/0003-e2e-against-built-extension.md)), so a stale or missing
build breaks them. `bun run test:e2e` in `apps/extension` runs `wxt build` first
and then `playwright test`; calling `playwright test` directly skips the build.
Playwright's Chromium is a separate one-time install.

**Fix:**

- Run `bun run test:e2e` from the repo root, not `playwright test`.
- Install the browser once with `bunx playwright install chromium`. Never use
  `--with-deps` or `sudo` locally; only CI does that.
- Related: the release workflow once never uploaded `.output/*-chrome.zip`
  because `upload-artifact` skips hidden paths. It now sets
  `include-hidden-files`; keep that when editing `release.yml`.

## lychee reports a broken link or anchor

**Symptom:** The `Lint Docs` workflow fails on a pull request, or
`bun run lint:docs` fails locally.

**Cause:** `.github/workflows/lint-docs.yml` runs lychee with `--offline` and
`--include-fragments=anchor-only` over the repository's own markdown. It never
dials external URLs, so every failure is a relative path that does not exist or
a `#heading` anchor that does not resolve. Renaming a heading or moving a file
breaks every link to it.

**Fix:** Open the failing file, correct the path, or update the anchor to the
GitHub slug of the heading (lowercase, spaces to hyphens, punctuation dropped).
Run `bun run lint:docs` before pushing. External links are intentionally not
checked, so a dead external site does not fail CI.

## A forge worktree fails typecheck or cannot be claimed

**Symptom:** `tsc` fails in a fresh `/forge` worktree with missing generated
types, or the worker cannot lock its worktree.

**Cause:** `apps/extension/.wxt/` is generated by `wxt prepare`, which runs from
the `postinstall` script. A new worktree has no `node_modules` and no `.wxt/`
until `bun install` runs. The first action of a worker is `git worktree lock`
with the coordinator's reason; a stale lock from an earlier run blocks it.

**Fix:** Run `bun install --silent` in the worktree before `bun run check`. If a
lock is stale, run `git worktree unlock .` and lock again with the reason the
coordinator gave. See [`agents/forge.md`](agents/forge.md#worktree-setup).

## BrowserStack run fails, is skipped, or opens an issue

**Symptom:** The `BrowserStack` workflow is red or skipped, or an issue titled
`Nightly BrowserStack run failing` appears.

**Cause:** The run is informational and not part of `CI passed`
([ADR 0024](adr/0024-cross-browser-coverage-on-browserstack.md)). On fork PRs
the secrets are unavailable, so the job skips with a notice. The nightly full
run opens or updates that issue on failure and closes it after a passing
nightly. Concurrent PRs can exceed the five parallel sessions, which only queues
sessions and lengthens wall time. A real iPhone is not automated
([ADR 0025](adr/0025-real-iphone-is-not-automated-on-browserstack.md)), and the
extension itself is manual-only.

**Fix:** Read the job log and download the `browserstack-report-<platform>`
artifact. Rerun one platform from Actions, BrowserStack, Run workflow. Locally,
export your own `BROWSERSTACK_USERNAME` and `BROWSERSTACK_ACCESS_KEY` and run
`bun run test:e2e:browserstack` from `apps/site`. Details:
[cross-browser testing](development.md#cross-browser-testing).

## The Coolify deploy fails

**Symptom:** The `Deploy Site` workflow fails after a push to `main`.

**Cause:** Seen so far:

- HTTP 405 on the trigger: Coolify Cloud rejects `GET /deploy`; the trigger must
  be `POST` (GET stays for polling status).
- HTTP 401: the `COOLIFY_API_TOKEN` secret was rejected and needs replacing
  ([ADR 0022](adr/0022-coolify-token-as-github-secret.md)).
- Missing `<lastmod>` in `sitemap.xml`, or lost dates: the token lacks the
  `write` ability, or **Use Docker Build Secrets** is on for the app, so
  `LAST_MODIFIED_DATES` never reaches the build.

**Fix:** Check the status code in the job log, then follow the matching case.
Revoke the old token in Coolify when replacing it. See
[site deploy](development.md#site-deploy).
